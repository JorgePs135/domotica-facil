Dónde pegar el YAML

Has encontrado o generado el YAML de una automatización y no sabes dónde pegarlo. Dos formas seguras, con sus errores típicos.

Revisado el 16/10/2026 · Home Assistant 2026.10 · Todos los tutoriales

Pasos revisados contra la documentación oficial de Home Assistant 2026.10. Los nombres de los menús pueden variar ligeramente entre versiones.

El problema

En foros, vídeos y generadores encontrarás automatizaciones escritas en YAML. Si las pegas en el sitio equivocado o con la sangría mal, Home Assistant no las guarda o, peor, deja de cargar la configuración. Aquí tienes las dos formas seguras de añadirlas.

Antes de empezar

  • Un usuario administrador de Home Assistant.
  • Las entidades que use la automatización ya integradas (las ves en Herramientas para desarrolladores → Estados).
  • Home Assistant 2024.10 o posterior si el YAML usa la sintaxis nueva (triggers:, trigger: state, action:). La sintaxis antigua sigue funcionando.

Opción 1 (recomendada): el editor de automatizaciones

  1. Ve a Ajustes → Automatizaciones y escenas y pulsa Crear automatización.
  2. Elige Crear nueva automatización (empezar desde cero).
  3. Abre el menú ⋮ de arriba a la derecha y elige Editar en YAML.
  4. Borra todo lo que aparece y pega el YAML. Debe empezar por alias:, sin guion delante.
  5. Pulsa Guardar. Si vuelves a ⋮ → Editar en el editor visual verás la automatización en el editor de bloques: es una buena prueba de que se ha entendido.

Home Assistant guarda la automatización en automations.yaml y le pone un id por su cuenta. La documentación oficial pide no editar ese archivo a mano porque lo gestiona la interfaz (Automatizaciones en YAML).

Opción 2 (avanzada): un archivo YAML propio

Útil si guardas tu configuración en Git o quieres tener tus automatizaciones fuera de la interfaz. El generador lo ofrece como «Archivo YAML propio».

  1. Crea, junto a configuration.yaml, un archivo automatizaciones_domotica_facil.yaml y pega dentro el YAML (en este formato cada automatización empieza por - id:).
  2. Añade a configuration.yaml esta línea, sin borrar la que ya tengas de automation: !include automations.yaml: 
    automation domotica_facil: !include automatizaciones_domotica_facil.yaml
  3. Ve a Herramientas para desarrolladores → YAML y pulsa Comprobar configuración. Si no ves la opción, activa el Modo avanzado en tu perfil de usuario.
  4. La primera vez, reinicia Home Assistant para que lea el nuevo !include. Después, cuando cambies solo el archivo, basta con Recargar automatizaciones.

Las automatizaciones de un bloque con nombre propio (automation domotica_facil:) aparecen en la lista, pero no se pueden editar desde la interfaz: se cambian en el archivo.

Sintaxis antigua y nueva

Desde Home Assistant 2024.8 y 2024.10 cambiaron algunos nombres. Las dos formas funcionan, pero no se pueden mezclar en el mismo nivel.

AntesAhora
trigger: (lista principal)triggers:
condition: (lista principal)conditions:
action: (lista principal)actions:
- platform: state- trigger: state
- service: light.turn_on- action: light.turn_on

Errores frecuentes

  • Sangría con tabuladores o desigual. YAML solo admite espacios. Pega el código tal cual y no lo reindentes a mano.
  • Pegar una lista en el editor. Si el YAML empieza por - id: es para un archivo (opción 2). En el editor (opción 1) quita el guion y el id, o genera el formato «Editor de Home Assistant».
  • on y off sin comillas. En YAML, to: on sin comillas puede leerse como verdadero/falso y no como el estado «on». Escribe to: "on".
  • Entidades que no existen. Home Assistant guarda la automatización, pero no hará nada. Copia el ID exacto desde Estados.
  • Mezclar service: y action: o platform: y trigger: dentro del mismo bloque.

Cómo comprobar que funciona

  1. En la lista de automatizaciones, abre la tuya y usa ⋮ → Ejecutar acciones: ejecuta las acciones sin esperar al disparador ni mirar las condiciones. Sirve para comprobar que las entidades responden.
  2. Provoca el disparador de verdad (o simúlalo, como se explica en Probar automatizaciones sin dispositivos).
  3. Abre ⋮ → Trazas: verás qué disparó la automatización, qué condiciones pasaron y en qué paso se paró (Depurar automatizaciones).
